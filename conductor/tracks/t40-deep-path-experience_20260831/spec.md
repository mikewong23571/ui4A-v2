# T40 深路径体验闭环:应用内实体页 × Chat 共同注视 — Specification

## 类型

**Remediation(走查修复 track)**,与 T35 同构但生命周期有界:以 2026-08-31 双环境走查
(`findings.md` F-01~F-08)为输入,修复闭环后按 `user-stories.md` S1–S10 深路径验收关闭。
`depends_on` T35/T39(消费其读面姿态、减暴露与 Application 入口现状,不推翻)。

## 方向依据(北极星,`conductor/product-vision.md`)

- §一.2 **Native context aware**:F-01 是坏的上下文处置——focus 携带的虚主体/失效实体被
  静默传播进会话起步,得到的是裸错误码。上下文必须来自客户端事实,缺失应得**结构化、
  人话、可降级**的回执,而不是起步阻断。
- §二 **同一扇门**:F-02(列表中文/详情英文两种状态词)与 S4/S6(助手引用同一实体、知道
  自己做成了什么)是"AI 看到的和你看到的是同一个东西"的最小闭环。
- §三 **workstation 是家,raw 是验钞灯**:F-03(实体页无字段/来源/审计分层)与 F-06
  (flow/collection 机械标签直出)是 raw 蔓延与机制 chrome 回潮;修复方向是把 T28 的
  field-role/raw 分层消费到业务实体页,raw 保持局部可展开。
- §五 **减法减暴露,加法加聚合**:F-04 空态引导、F-05 术语中文化是减暴露;工作线详情
  聚合(F-08 裁定项)是加法——都只动投影与合同数据,不加新真相。
- §六 **施工纪律(反向约束)**:
  - **文案滑梯**:状态词、术语、错误人话的修复一律落在**合同数据/通用文案框架**
    (定义/动作/字段 title、守卫原因结构化、D47.1 插值),渲染器不新增字符串模板。
  - **特判滑梯**:实体页分层、机械标签退守必须在通用 generic/组合渲染机器上修,
    `if entity.class === 'todo'` 一行即背叛。
  - **页面滑梯**:不新增任何 per-app/per-实体类型页面;深路径由合同与组合机器供数。
  - 固定评审项:无每应用/每实体类型特判代码;无 React 文案翻译表。

## 背景与动机(2026-08-31 双环境走查)

以当前代码对本地 dev(web:3100)与 mothership 部署实例(登录态)做双环境走查,登记
`findings.md` F-01~F-08,证据存 `evidence/2026-08-31-walkthrough/`。核心断裂只有一条但
位置致命:**F-01——共同注视场景下 chat 起步即败**(`start_entity_unavailable` 裸码直出),
它把"看着对象跟助手说话"这个 AI-first 主入口在起点关上。其余为读面表达层:实体页状态词
裸露(F-02)、实体页分层单薄(F-03)、首页空态裸标题(F-04)、Meta 术语未译(F-05)、
机械标签泄漏(F-06)。现场另登记认证一致性待核项(F-07)与来源标识观察项(F-08)。

## 核心目标(一句话与判定要点)

**让"书架 → landing → 动作 → 实体页 → chat"这条深路径在每个应用上全程可走、每屏说人话、
人机同门——以 `user-stories.md` S1–S10 的浏览器实测为唯一验收。** 判定要点:

1. chat 在任何合法/失效 focus 下都能起步,失败说人话且可行动(F-01);
2. 任一业务实体页首屏回答"是什么/什么状态/能做什么",状态词中文、字段分层、机械标识
   退守(F-02/F-03/F-06);
3. 首页三区空态一致有引导,动作后与实体页一致(F-04);
4. Meta 治理面术语全中文任务语言(F-05);
5. 双门同径:CLI/HTTP 与浏览器同事实同动作;390px 深路径可用。

## 范围

**In scope**

- Chat 起步的 focus/entity 解析与降级回执(F-01);
- 业务实体页读面:状态词、字段分层、机械标签退守(F-02/F-03/F-06);
- 首页"在等我/在动"空态(F-04);
- Meta 控制台术语(F-05)与工作线来源可读性裁定(F-08);
- S1–S10 深路径验收,含真实 LLM 故事与现场复核(F-07 裁定)。

**Out of scope / 禁止事项**

- 不重做业务引擎、judge/fold、事件模型;不改授权语义(D51 不被削弱);
- 不新增 per-app/per-实体类型页面、组件或渲染分支;
- 不在 React/渲染器写文案翻译表或状态词映射(文案走合同数据);
- 不建设 chat 的意图启发式或 rule driver 兜底(AI-first);
- 不新增 per-track Playwright 配置(沿用 agent 浏览器实操验收);
- 部署版本升级本身不作为本 Track 任务(现场复核只验证形态、登记差异)。

## 验收协议

1. **故事验收**:`user-stories.md` S1–S10 由编排 agent 浏览器实测逐条判定,加粗句任一不成立
   即不通过;截图存 `evidence/<date>-<story>/`;S4/S6 需真实 LLM,provider 缺失记 NOT RUN。
2. **双门**:S10 的 CLI/HTTP 同门对照使用仓库 `ui4a-cli` 技能;合同事实、动作集、守卫与
   浏览器所见一致性逐一比对。
3. **代码护栏**:每 Phase Red→Green 的最窄测试先行;改动面执行 focused tests、typecheck、
   `pnpm governance:strict`;Track 末跑全量 `pnpm check` 与 `CI=true pnpm e2e invariants`。
4. **门禁复核**:GR1–GR5、D47.1/D47.4/D51、T24 减暴露、T28 披露层级为固定评审项;
   任何"渲染器新增字符串模板/状态表"的 diff 即打回。
