# T40 用户故事(文档化视觉验收锚)

> **本文件是什么**:T40 的验收准绳。每个故事是一条**完整深路径**——从入口一路走进
> 应用内的实体页面,并继续走进 chat 交互;验收方式是**编排 agent 以使用者身份在真实
> 浏览器里按步骤实测,用视觉能力对照本文档逐条判定**,截图存 `evidence/<date>-<story>/`。
>
> **本文件不是什么**:不是单测断言、不是代码验收清单。**禁止以单测/代码检查替代故事
> 验收**;代码层测试只作语义回归护栏(见 spec 验收协议)。
>
> 判定纪律:期望效果里每一条加粗句都是可判定的视觉事实;任何一条不成立即故事不通过,
> 偏差回填 `findings.md`(新编号或挂靠既有编号),修复后重走。
> 验收环境:本地 dev(web:3100)为主,S4/S6 需真实 LLM 配置;S10 含现场实例复核。
> 真实 LLM 故事在 provider 缺失时记 NOT RUN,禁止 rule/scripted driver 冒充。

## S1 待办全链路:从书架到实体页再回首页

- **角色**:想用待办应用管理琐事的使用者。
- **场景**:首页书架 → todo landing → 捕捉一条待办 → 进入它的实体页 → 完成它 → 回首页确认。
- **步骤**:
  1. 打开 `/`,在应用书架点「待办事项」卡片;
  2. 在 landing 点「添加待办」,标题填"写周会纪要",备注填"含上周行动项回顾",提交;
  3. 在列表点该待办标题,进入实体页(`/canvas?focus=todo:…`),停留观察;
  4. 在实体页点「完成」,停留观察 3 秒;
  5. 回 `/` 观察「在动/在等我」与「我的工作线」区域。
- **期望效果**:
  1. **landing 首屏能看到应用标题、用途说明和"开始做事"的动作入口**,不是只有描述卡;
  2. **实体页首屏回答三件事:这是什么(标题)、什么状态(中文状态词)、能做什么(动作)**;
     **备注字段内容可见**;**不出现 `open`、`flow flow:…`、`collection …` 等机械标识作主文案**;
  3. **点「完成」后状态当场变为已完成,动作区当场换成当前可用的下一批动作**;
  4. **回首页后该待办的最新状态在相关区域与实体页一致**(屏上即真相);
  5. 全程无整页白屏、无"点了没反应";**原始合同始终可从次级入口到达,不占首屏**。
- **关联**:F-02/F-03/F-04/F-06;证据基准 `entity-page-raw-status.png`、`canvas-mechanical-labels.png`。

## S2 写作深路径:brief → 实体页 → 人类决策点

- **角色**:编辑写作应用的使用者,把一篇有来源约束的稿件交给 Writing Agent。
- **场景**:editorial landing → 发起写作 → 跟踪到实体页 → 在责任点做接受/驳回。
- **步骤**:
  1. 书架点「编辑写作」;在 landing 点「开始写作」;
  2. 按表单填写 brief(题目、来源约束各一),提交;
  3. 从"写作记录"进入新实体页,观察进度呈现;
  4. 等 agent 执行有进展或终态(无 Temporal/executor 时观察诚实失败),在实体页找责任点。
- **期望效果**:
  1. **提交后实体页可见,状态词为中文,进度/文档/引用/渲染证据有分层位置**;
  2. **执行环境不可用时,实体页呈现结构化的人话失败与下一步建议,不是空白或裸错误码**;
  3. **到达待决策状态时,首屏显示"需要我决定什么",接受/驳回只来自当前动作集**;
  4. **"接受不等于发布"的业务语义在页面上可读**(文案或状态分层其一);
  5. 表单字段有必填与人话说明;**server-owned 字段不作为输入框出现**。
- **关联**:F-02/F-03;证据基准 `editorial-landing-current-ok.png`。

## S3 实体页读面(通用约定)

- **角色**:任何应用的使用者,打开任何一个业务实体。
- **场景**:对 todo 实体、写作请求实体、文章实体各做一次。
- **步骤**:从各应用列表/集合点进实体页,观察首屏与次级层。
- **期望效果**:
  1. **每个实体页首屏都回答:这是什么、当前状态(中文)、为什么值得看、下一步能做什么**;
  2. **声明过的业务字段按概览/详情分层出现**;未填字段不渲染空壳噪音;
  3. **机械信息(rel、kind、class、collection 归属)退守次级或原始合同层**,不作主文案;
  4. **原始合同局部可展开**,内容即授权后的 exact Siren JSON;
  5. 三个应用的实体页遵守**同一套呈现约定**,无 per-app 观感跳变。
- **关联**:F-02/F-03/F-06。

## S4 Chat 共同注视:看着实体跟助手说话(真实 LLM)

- **角色**:正在实体页上工作的使用者,想就地求助。
- **场景**:在 todo 实体页打开聊天(focus 携带该实体),就地提问与求推进。
- **步骤**:
  1. 进入某 todo 实体页;打开聊天面板/页;
  2. 发送"这个待办现在什么状态?帮我把它完成";
  3. 观察助手回答与画布/实体页。
- **期望效果**:
  1. **聊天能正常起步**(无 `start_entity_unavailable` 类阻断);
  2. **助手的回答引用的是同一实体的事实**(标题/状态一致,不张冠李戴);
  3. **推进类请求给出确认或动作后果,执行后实体页状态当场变化**;
  4. **顶栏/聊天区能看出"助手知道你在看哪个对象"**(注视 chip 或会话上下文其一);
  5. 助手引用事实处可点击回到该实体(T28 FactRef 纪律)。
- **关联**:F-01;真实 LLM 必跑,provider 缺失记 NOT RUN。

## S5 Chat 失效 focus 的诚实降级

- **角色**:从一个已失效/不可见的上下文进入聊天的使用者。
- **场景**:携带不存在或授权外的 focus 进入聊天(如已删除实体、workspace 虚主体)。
- **步骤**:以失效 focus 打开聊天,发送"你好,介绍一下你看到的东西"。
- **期望效果**:
  1. **聊天起步不被阻断**,会话可用;
  2. **回执用人话说明"看不到你指的那个对象"+ 给出下一步**(如回到书架/我的事),
     **不出现裸错误码或内部 rel 作主文案**;
  3. **结构化失败细节退守可折叠区域**,与 T35 失败回执同形;
  4. 随后正常提问(不带失效上下文)能正常进行。
- **关联**:F-01;机制部分可无 LLM 验收,人话回执的表述质量在真实 LLM 下复核。

## S6 Chat 推进业务并自我认知(真实 LLM)

- **角色**:想用一句话让助手办事的使用者。
- **场景**:在 chat 里发起一个动作,并验证助手知道自己做成了。
- **步骤**:
  1. 打开 `/chat`,发送"帮我添加一个待办:整理 UI 走查照片";
  2. 按确认门完成授权;观察画布/列表;
  3. 紧接着问"你刚才做了什么"。
- **期望效果**:
  1. **助手给出动作提议与后果说明,确认后执行,不静默执行**;
  2. **执行后 todo 列表/实体可见该待办**,从 chat 引用可点进实体页;
  3. **助手能说出刚做成的动作与结果**(目标已达成不循环重试、不错标失败);
  4. 全程无重复追问同一授权、无动作重放。
- **关联**:F-01 连带;真实 LLM 必跑,provider 缺失记 NOT RUN。

## S7 工作线深路径:一件事串起实体与 chat

- **角色**:用工作线推进"一件事"的使用者。
- **场景**:创建工作线 → 挂上涉及对象 → 从线进实体 → 在线的上下文里用 chat 推进 → 线投影反映进展。
- **步骤**:
  1. 首页「创建工作线」:标识 `weekly-report`,目标"产出本周 UI 周报",来源 `chat:walkthrough`;
  2. 进入该工作线详情,「添加涉及对象」挂上 S1 的待办;
  3. 从涉及对象点进 todo 实体页,再返回工作线;
  4. 在工作线详情打开 chat,发送"这条线现在进展如何";
  5. 完成该待办,回工作线详情观察。
- **期望效果**:
  1. **工作线详情首屏显示目标、状态、涉及对象(可点)与可用生命周期动作**;
  2. **涉及对象可一键到达实体页,返回路径连续**(视角/注视不丢);
  3. **工作线上下文里的 chat 起步正常,助手回答引用线内对象事实**(无 LLM 时至少验证起步与降级形态);
  4. **待办完成后,工作线详情的进行中/近期信息反映该变化**;
  5. **"来源"以可读物显示或退守次级**,不裸占首屏主文案。
- **关联**:F-01/F-08;证据基准 `deployed-thread-source-uuid.png`。

## S8 首页读面:三区的一致空态与有态

- **角色**:每天打开 UI4A 的使用者。
- **场景**:空态(无任何待办/进行中)与有态(S1 完成后)各看一次首页。
- **步骤**:空库观察 `/`;制造一条待办、一条进行中事项后再观察 `/`。
- **期望效果**:
  1. **空态下「在等我」「在动」各有一句引导或干净留白,不是裸标题**;三区视觉约定一致;
  2. **有态时 3 秒内能说出:什么在等我、什么在动、有几条线、线停在哪**;
  3. **动作完成后回首页,相关区域当场或导航后即与实体页一致**;
  4. 导航、区块、实体页对同一状态用同一个中文词(F-02 口径延伸到首页)。
- **关联**:F-04/F-02;证据基准 `home-empty-sections.png`。

## S9 Meta 治理深路径:从控制台到 Flow 详情

- **角色**:定义维护者,巡查定义资产。
- **场景**:定义控制台 → 流程定义集合 → 任一 flow 详情 → 返回,全程 editorial 视角。
- **步骤**:
  1. 进入 `/meta?scope=editorial`,观察控制台分组与术语;
  2. 点「流程定义」进入集合,任选一个 flow 进详情;
  3. 在详情查看拓扑/动作/版本与关系,然后返回控制台。
- **期望效果**:
  1. **控制台所有分组与卡片标题为中文任务语言**,无 Governed Drafts/Specialized Agents 类未译术语;
  2. **flow 详情首屏显示业务标题、状态、版本与可用动作**,拓扑/节点摘要随后;
  3. **返回路径保留 editorial 视角**(顶栏 chips 与 URL 不丢);
  4. **集合计数为"数词+对象+状态"完整文案**,无裸数字;
  5. 全程不依赖 raw 即可完成巡查;raw 仍可局部展开。
- **关联**:F-05;证据基准 `meta-untranslated-terms.png`。

## S10 双门同径与窄屏深路径

- **角色**:验收者(编排 agent 代行)。
- **场景**:同一深路径,人类走 renderer、agent 走合同,各跑一遍;窄屏再过一遍人类路径。
- **步骤**:
  1. 用 CLI/HTTP 完成 S1 等价路径(discover → 读合同 → exec 创建/完成 → 读回实体与集合);
  2. 用 CLI/HTTP 读 S4 的同一实体,比对事实与动作集;
  3. 390px 视口走 S1 与 S7 人类路径。
- **期望效果**:
  1. **CLI/HTTP 读到的事实、动作、守卫与浏览器所见同源一致**(同一事件日志);
  2. **chat 起步降级对 agent 侧同样为结构化回执**,无第二套错误语义;
  3. **390px 下实体页/工作线/chat 无页面级横向滚动**,动作不遮挡正文;
  4. 现场实例(mothership)复核 S1/S4 形态,并顺带裁定 F-07 归属。
- **关联**:F-01/F-07;CLI 使用仓库技能 `ui4a-cli`,现场复核走登录态浏览器。
