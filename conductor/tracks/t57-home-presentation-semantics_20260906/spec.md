# T57 Spec

## 1. 目标

首页成为由当前处境组织的工作简报：用户能知道当前可见的责任、可以继续的工作、如何发起目标，
无需先选 application 或理解机器标识。组件按阅读/选择/比较/决定/输入的任务选择，
内容仍由合同与 Presentation 驱动，换 application 不改通用 UI。

“需要我／继续工作／发起工作”是应回答的问题，不是三个必须常驻的 React 面板。
首页负责分配注意力，T56 工作线主面负责深入一件事，两者共享事实、导航和动作语义。

- 在等我/在动均为空，仍各占大区域；已完成/已归档工作线在主列表。
- 已完成工作线展开添加、手动输入、移出、恢复和归档整组管理动作；重复合同图例和机器 rel。
- 创建表单要求工作线标识、目标、目标来源；必须理解短名字规则和引用格式才能开始。
- 助手主要通过悬浮图标进入，首屏没有直接表达目标或询问当前工作的明显入口。

最终必须用隔离 fixture 重现，不依赖这两条历史工作线或现有线上数据仍在。

## 3. 功能要求

### FR01 首页注意力与覆盖口径

在同一 my-work Presentation 下按授权事实组织当前责任、可继续工作、最近结束和发起入口。
当前工作优先于已结束；历史单独收纳但仍可到达。存在责任时责任不得藏在历史/更多操作中。
真正空状态用轻量状态行，无责任但有进行中工作时凸显继续入口，无进行中工作时凸显发起入口。
来源失败显示可恢复失败，授权裁剪同形按 D78.3 只说“当前可见”；不披露被裁对象或数量。
不能把 delegations 为空说成所有业务都没在推进；来源覆盖由 P0 定案，必须同时呈现真实的在途工作线。

### FR02 组件姿态来自任务语义

普通工作摘要用列表行；当前人类责任用决定卡；可比的多对象属性用表格；局部详情用展开；
长材料进入主面。动作存在性不能单独决定所有成员都变为展开决定卡，也不能单独决定是否用表格。
认知 traits/声明 intent 为依据，未知语义使用安全、可发现动作的 generic 展示，不猜责任。
生产不得出现 `if app/flow/entityName === ...` 或用自然语言/业务状态字串推断组件。

### FR03 动作披露与责任不混淆

摘要行默认突出进入/继续，低频管理动作收在次级入口；当前责任保留显著查看/决定入口与完整依据。
移动位置不改变 action、guard、schema、审计或实际作用目标；动作集合始终可经 fresh 合同到达。
“有动作”“需要人处理”“需要确认”“危险/不可逆”分别表达，不互相替代。
不得根据 high 直接宣称不可逆或服务端必需 human；A5 现状明确保留，相关风险语义见 design。

### FR04 表单宿主与组件职责

保留现有 RJSF/ActionRunner，参数和校验来自合同；按任务将短局部输入内联，
独立短任务用 Dialog，需要同时参考材料时用非模态侧面/主面，长任务进入主面。
更多菜单只用于选择命令，不容纳复杂表单；打开/取消/换布局不提交业务 mutation。
提交中、失败、重试、关闭再开均保留有意义的草稿/回执；防重复点击与陈旧 schema。
不以 Dialog 替换一切，不新增全局表单工作流引擎。

### FR05 低成本且来源真实的发起

用户从首页发起工作主要填写目标，可选择已有真实来源材料；不必手填 id 或裸 goalSource。
目标输入可直接通过合同创建（不依赖模型），也能交给现有助手讨论/澄清；两种意图明确，不自动互换。
系统生成的标识、来源引用有可验证契约与原始记录，客户端/CLI/Agent 同门；
不编造 messageId、不拿 sessionId/随机串冒充来源、不静默丢 required 字段。
P0 必须先证明来源接线、重试/幂等、权限和 replay；只把字段藏起来不算完成。

### FR06 助手共用入口与共同处境

首页有明显、紧凑的目标/提问入口，调用既有 Chat session/runtime，复用 T56 的响应式宿主与草稿。
不新建另一个聊天 store/输入流水线、不在加载首页时自动发问、建线或执行。
“这里哪些在等我”应以首页授权来源事实回答；当前首页观察与实际 clientView/薄呈现引用一致。
不把 workspace 虚主体伪装成新的业务实体；不向 prompt 灌入全量事实。

### FR07 视觉与可访问性

一个清晰 H1，业务内容优先；状态只表达一次，机器 id/raw/why/合同图例按需披露。
无重复卡片嵌套和大块空面板，关键标题/动作可读；正文不靠小字/整页横滚解决拥挤。
1440/1080/768/390px 与 200% 缩放下可完成用户故事；菜单/展开/Dialog 按各自键盘、
焦点及 ARIA 模式实现，重要信息不依赖 tooltip/hover；失败与完成回执可读。

### FR08 应用发现与工作连续性

应用入口轻量保留，完整目录可达，首页应用最多 9 个上限不变；不写固定应用名/顺序/图标清单。
进入工作线保留 T56 链接与 currentView；返回首页恢复合理的列表位置，草稿与会话不被重置。
用户只有未知 application 或无工作时仍可发现能力，不让新应用被硬编码首页排除。

### FR09 呈现改变不改事实或审批权

单一 PostgreSQL 事件日志；工作线仍显式成员、principal-owned；D51 授权/注意力分离；
薄 Presentation、binding-only、Sidecar/Recipe 逐源重授权与依赖失效、human-only approve 不变。
列表/卡片/个人 Sidecar/共享 Recipe 四条路径都保留当前责任与动作可达；
模型不可用时人工入口可用，不用规则驱动冒充助手。

### FR10 小规模语义扩展与机械治理

先比较已有 traits、catalog words、输入来源注解与 UI primitives，只有两个不同域故事均需要时
才补通用语义/词汇。业务 cognitive 不放 componentName、pixelWidth、颜色或布局 DSL。
扩展 D54 针对已确认的 planner/words/actions 路径，使用低误报正负例并补跨应用语义测试；
模块超限沿功能拆，禁止为规避路径扫描把逻辑搬出扫描集。

## 4. 非目标

- 不实施 T56 本线重构；不新增第二工作线主体、第二助手、第二状态源或新的 UI 编排框架。
- 不改变工作线 lifecycle/审批合法性；D78.4 的 thread 确认门差异保留为已知问题，绝不假称修复。
- 不做全站菜单/Meta 重设计、全应用组件替换、推荐评分器、计划自动推进或独立任务管理器。
- 不部署、推送、改认证/模型/域名、清理生产或体验数据；不因架构审查启动无关大重构。
