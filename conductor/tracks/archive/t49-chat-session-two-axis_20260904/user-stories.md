# T49 聊天会话双轴 — 用户故事(验收入口)

> 本文是 T49 的产品验收入口。故事描述用户应获得的结果,不规定实现算法。每条故事标注验收锚点(A = 单测/路由测试;C = 组件测试;E = E2E);plan.md 的任务与故事一一对应,全部故事闭环方可 DONE。

## 会话生命周期

### U1 生产环境多会话并存(A/C/E)

同一生产账号完成两轮对话后点击「新会话」再完成一轮。打开「历史会话」清单,应看到**两条**会话:第一条含前两轮、第二条含第三轮;清单按最近活跃排序,每条显示回合数与末回合摘要。不得再出现「永远只有一条会话」。

- 锚点:route 级生产测试(同 principal、两个 sessionId → 清单两行);组件测试(清单多行渲染);E2E(本地 profile 同路径)。

### U2 「新会话」即干净上下文(A/C)

用户点击「新会话」后在空白界面发送新目标。Assistant 的认知上下文——近期原文与结构化会话状态(活动目标、指代、约束、待澄清)——**不得包含旧会话的任何回合**;旧会话中的指代(如"那篇文章")在新会话中不得被静默沿用。生产与本地行为一致。

- 锚点:路由/装配测试(同 principal 下新 sessionId 的 `loadAgentConversation` 返回空会话);组件测试(新会话后消息区清空且不回放旧会话)。

### U3 切换回旧会话并继续(C/E)

用户在清单中点选旧会话。消息列表完整重放该会话全部回合;在同一会话内继续追问,Assistant 仍能解析该会话内已建立的指代与约束。切换不丢失、不串台其他会话的回合。

- 锚点:组件测试(selectSession 重放);E2E(切换后继续对话,回应可追溯旧会话上下文——本地 profile)。

### U4 刷新后继续当前会话(E)

用户刷新页面(或重开独立聊天窗 /chat)。当前会话经 localStorage 恢复,历史回合完整重放;进行中的回合继续轮询至终局。此为既有能力,本 track 不得回归。

- 锚点:E2E 回归(刷新重放,含 running 轮询路径)。

## 身份与隔离(负向)

### U5 自报 sessionId 不构成身份(A)

生产模式下,客户端自报任意字符集合法的 sessionId(包括伪装成他人 principal 形状的字符串)。该值只能作为本人名下会话的分组键;**任何事件的 principal 恒为认证主体**,伪造值绝不出现在身份绑定字段。客户端不传 sessionId 时,服务端代铸新 UUID 并经 `session` 帧回传,客户端持久化自愈。字符集非法(超长/非法字符)的请求得到 400 结构化拒绝,不落库、不 5xx。

- 锚点:路由测试(伪造 principal 形状 sessionId → 事件 principal=认证主体;缺省 → 代铸 UUID 经 session 帧下发;非法 → 400)。

### U6 跨用户会话不可见(A)

用户 A 无法通过在请求中携带用户 B 的 sessionId 而读取 B 的任何东西:会话清单、历史回合、消息原文三路都按请求者 principal 过滤,B 的回合对 A 表现为不存在(空态,非错误)。

- 锚点:路由测试(sessions/history 双端点跨 principal 不可见)。

### U7 sessionId 碰撞不污染 agent 上下文(A)

两个 principal 恰好使用同一 sessionId 字符串(碰撞或恶意)。回合前的会话上下文装配只纳入**本人 principal** 名下的事件;他人的消息、指代、约束绝不进入我的 Agent 上下文与 UI 重放。

- 锚点:装配测试(loadAgentConversation 双 principal 同 sessionId,互不可见)。

## 数据诚实与审计

### U8 旧数据诚实投影(A/E)

升级部署后,修复前已落库的回合(sessionId=principal 形状)在清单中保留为一条可读的历史会话行;用户在新模型下创建的会话与其并存。不迁移、不改写、无双轨;旧客户端 localStorage 中的旧值合法延续为该旧会话,点「新会话」即进入新模型。

- 锚点:路由测试(混合旧形状+新 UUID 事件的清单投影);E2E(预置旧形状事件后清单并存)。

### U9 审计口径不回退(A)

修复后审计查询按 principal 仍可取该用户**全部**会话的全部 chat 事件(原话、轨迹 steps、决策留痕);sessionId 只是分组维度。生产双通道(human/agent)事件的 actor/principal 语义与 T22 口径一致,不因解耦而松动。

- 锚点:路由测试(同 principal 多会话事件全量可查、actor 口径断言复用既有 forged/credential 用例)。

## 一致性

### U10 双 profile 同语义(A/E)

同一套用户操作——发送、新会话、清单、切换、刷新——在本地 demo 与生产 profile 下行为一致;唯一差异是身份来源(本地 `user:<sessionId>`,生产认证主体)。不存在"本地多会话、生产单会话"的分叉,也不存在校验规则的 profile 分支。

- 锚点:请求体校验纯函数单测(无 profile 分支);本地 E2E 与生产 route 级测试断言同构行为。
