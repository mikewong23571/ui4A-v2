# T42 共同工作上下文

## 目标

实现 product-vision 的同一入口和工作线 scoped context：应用只是归属/发现维度，
不是整件事的围墙。用户不必学习 scope，也不必为了跨应用问答反复切换应用。

## 用户授权与优先级

用户要求新建 Track 并按 workflow 全程自治验收；用户故事先于实现。现存测试若
固化了错误默认或旧文案，修正测试而不迁就错误行为。权限、来源、审批、重放及
预算不变量不因修改测试而放松。前端不增加解释段落、教程、口号或额外卡片。

## 功能与边界

1. 未定位的业务 Assistant 从全部已授权应用的简要合同发现，不默认读取 articles。
   明确的实体/Meta 集合保持原起点；工作线存在且无具体对象时以工作线起步。
2. 应用选择、工作线、客户端焦点和 Agent 合同读取位置分别保留；显式 null 清空
   不被旧 presence 恢复。已授权集合只限制访问，不凭空创造应用选择。
3. 工作线目标及显式 context/active/approval 引用进入有界 Agent 输入，读取走现有
   HTTP/Siren 授权边界；无关键词成员推导、无自动 attach、无第二份业务状态。
4. 导航到其他已授权应用后披露当前对象所需合同，原用户应用选择不被改写；
   广域仅摘要、详情按需读取，完整 provider wire 继续 <=32 KiB。
5. inline 与 delegated 在工作线引用及按步重新读取方面语义一致；恢复不随之后的
   浏览器导航改写已派发上下文，不扩大凭证权限。
6. 应用选择显示合同中文标题而非 scope 术语；复用“在哪”弹层展示工作线、
   当前对象和有限关联对象链接。使用既有交互和状态，不新增说明段落。
7. CLI 继续使用相同合同，工作线可在 Chat 之外建线/挂接/查询；测试数据库隔离。

## 非目标

不新增 Scope CRUD、通用上下文配置系统、新数据库/运行时依赖/LLM 路由规则；不全仓改名，
不改变 OAuth scope、Draft 归属/配额或人类审批规则；不自动创建工作线、不隐式
扩张成员、不新增跨应用内容搬运工作流；不推送/部署、不清空开发数据库。

## 完成定义

user-stories 的 S1–S8 均有可复跑证据；针对性 Red→Green、全量 check、format、
Playwright 和真实 LLM 只读故事验证完成；截图覆盖桌面与窄屏，审查问题闭环；
每阶段提交和 git notes 记录自治验收，Track 归档。外部限制如实记为未完成而非假绿。

实施注：仓库缺少 workflow 覆盖率所需 provider，补充同版 @vitest/coverage-v8
开发工具，tech-stack 先记录；不引入任何产品运行时依赖。
