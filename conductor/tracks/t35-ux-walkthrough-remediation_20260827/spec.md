# T35 持续试用与走查修复 — Specification

## 类型

**Remediation(持续试用轨道)**。与 T14/T31/T32 修复 track 同构,但生命周期长期:
"试用 → 登记(`findings.md`)→ 修复 → 按 `user-stories.md` 视觉验收"循环推进,
阶段可闭合,轨道不随单轮修复关闭。`depends_on` T33/T34(消费其落地的读面姿态与
授权/注意力分离现状,不推翻)。

## 方向依据(北极星,`conductor/product-vision.md`)

本 Track 的每一项修复都能在北极星找到裁决依据;同样,北极星的纪律约束修复的**做法**:

- §一.1 **AI as assistant**:"AI 让你对工作保有完整认知,同时只做你明确要点头的部分"。
  F-04(代理在目标已达成后循环执行、会话结果错标)直接违反前半句——助手对自己
  刚做成的事没有认知。修复方向是给助手可靠进度事实,不是加步数上限之类的 hack。
- §一.2 **Native context aware**:上下文必须来自客户端事实,不来自启发式。F-02 的
  无效 focus 是坏事实:链接生成把 flow 定义当实例 focus;缺失目标应得**结构化**
  的空态/回执(D51:缺失为结构化 denied 回执),而非静默传播进会话上下文。
- §一.3 / §二 **同一扇门**:"AI 看到的和你看到的是同一个东西"、"canvas 跟着 AI,
  AI 跟 clientView"。F-03(聊天推进成功、人看的画布全是错误行)是对"同一扇门"的
  最直接违背,是本 Track 的正当性核心。
- §三 **workstation 是家,raw 是验钞灯**:F-14(原始实体页裸 presentation JSON)
  与 F-16(诊断细节上首屏)是 raw 蔓延;F-01 的验收口径沿用 T33——事件落库后
  刷新/导航即见投影变化,本 Track 把"刷新"的成本降为零(动作后当场可见)。
- §五 **减法减暴露,加法加聚合**:错误行聚合、self 空卡/双计数/样板句删除(F-06)
  是减法;工作线详情业务信息(F-11)是加法(投影聚合,不加新真相)。
- §六 **施工纪律(对本 Track 的反向约束)**:
  - **文案滑梯**:机械层禁止硬编码"友好文案"模板。文案类修复(F-08/F-09/F-10)
    的合法路径是**改合同数据**(定义/动作/字段 title 中文化、守卫原因结构化)与
    合同插值(D47.1 框架),人话增量归 LLM;渲染器不新增字符串模板。
  - **特判滑梯**:F-06(self 空卡/双计数)等 surface 缺陷必须在通用
    generic/组合渲染机器上修,`if entity.class === 'post'` 一行即背叛。
  - **页面滑梯**:术语统一(F-05)落在应用定义/流程定义的 title 与 sitemap 数据,
    不写 React 硬编码页面副本。
  - 固定评审项:无每应用/每实体类型特判代码。
- §八.2 **处境只有一个装配点**:任何刷新/失效修复不得在组件里二次计算处境或
  sidecar 键;沿用 situation 单点装配与既有 sidecar 键。

其余准绳:`DECISIONS.md` D47.4(actions 始终保留)、D47.1(通用文案框架 + 合同
插值)、D51(授权/注意力分离;注视只出自 situation 单点)、T33 验收口径
("不做自动推送;事件落库后刷新或导航即见变化"——本 Track 把它收紧为"动作成功
后当前 surface 当场活过来")。

## 背景与动机(2026-08-27 R1 全站走查)

以最新代码(e7891f1)对 web:3100 做了全站 GUI 走查(首页/画布/定义管理/聊天/
系统页/顶栏/历史会话),完整实情登记于 [`findings.md`](./findings.md) F-01~F-16,
证据截图存 `evidence/2026-08-27-initial-walkthrough/`。四条 P0 全部是闭环断裂,
且相互放大:F-02 死链污染注视 → 首页建议的示例任务在聊天失败(F-02 连带);
聊天能推进业务但画布 deref 全挂、错误行堆叠(F-03)→ 助手读不到自身进度而循环、
停止后成功被标失败(F-04);所有直操作成功后 surface 不刷新、零反馈(F-01)。
P1 集中在术语一物多名(F-05)、重复噪音(F-06)、层级缺失(F-07)与机制词汇
泄漏(F-08/F-09/F-10/F-16)。

## 核心目标(一句话与判定要点)

**把"动作→反馈""跨面跳转""人机同门"三条断掉的闭环接活,并把 R1 登记的 P1
表达问题(术语、噪音、层级、机制词汇)按北极星纪律收敛——验收以
`user-stories.md` 的文档化视觉走查为准。** 三要点缺一即偏:

1. **反馈 = 投影活过来**,不是加通知系统:动作成功后当前 surface 当场反映新状态
   (卡片退场、计数变化、状态词更新),页内"重新载入"不再必要(留但不承担救场职责)。
2. **坏事实进门就要被拦**:无效 focus 得到结构化空态与可操作恢复(调整声明/返回),
   不静默、不进会话上下文;"查看活实例"类跨面链接必须指向真实存在的集合。
3. **人机同门对人的那一半必须能读**:聊天推进时画布呈现与助手认知一致的可读进展
   (渲染成功则向导面,渲染失败则聚合、可操作的单条降级说明),杜绝同文错误行堆叠;
   会话成败与业务结果一致。

## 理想态用户故事(方向锚)

见 [`user-stories.md`](./user-stories.md) S1–S8。**故事是文档,验收是视觉走查**:
编排 agent 以使用者身份按故事步骤在浏览器实测,截图存 `evidence/`,与故事的期望
效果逐条比对,偏差回填 `findings.md`。**禁止以单测/代码断言替代故事验收**;
代码层测试(下述 plan)只是语义回归护栏,不是验收依据。

## 最终形态(实施目标)

1. **动作回执与 surface 失效(F-01)**:exec 成功后,与该实体相关的用户 sidecar
   失效/重算,当前 surface 重取;动作控件具备 pending 与结果回执的呈现通道
   (结构化,机械层零文案模板;轻量回执可选,投影更新是硬要求)。全站统一,
   不留"某些页会刷"的双路径(GR2)。
2. **跨面链接与无效注视(F-02)**:"查看活实例"指向真实实例集合;focus 解析失败
   时 canvas 呈现结构化空态(目标不存在 + 恢复入口),不写入会话上下文(与 D51
   缺失语义一致)。
3. **向导 surface 韧性与错误聚合(F-03)**:修复 subject 词元 deref undefined 的
   根因(新实例/空态下的绑定解析);同 surface 多条同类诊断聚合为一条可展开项;
   渲染失败时给可读的阶段说明(合同插值/LLM,不硬编码)。
4. **代理认知与结果一致性(F-04)**:助手在每步后消费可靠的进度事实(自身回执 +
   实体投影),目标达成即收敛;会话/turn 的成败标注对齐业务结果。
5. **术语与文案收敛(F-05/06/08/09/10/13/15/16)**:统一术语表落到定义/投影数据
   (一物一名);删双计数、self 空卡、重复样板句(D47.4 下动作仍保留,样板句不属于
   合同数据即删);"填写XX参数"框架回归动作语(改 action title 数据);助手澄清语
   与证据引用走 LLM 人话与结构化 chip(机械方言退出对话面,审计细节进可展开区);
   守卫原因携带结构化数据,由合同插值/LLM 转述。
6. **工作线投影补全(F-11)**:工作线详情呈现目标、状态人话、显式引用、近期事件
   (纯投影,T26 数据已在);动作分组,危险动作与普通动作视觉分层(F-07)。
7. **持续试用机制**:R2+ 轮次按本 spec 循环;`findings.md` 持续追加,已修复项
   回填复验记录;轨道保持 `[~]`。

## 验收协议(本 Track 特有,覆盖 workflow 默认)

- **故事验收 = 文档化视觉走查**:编排 agent 按 `user-stories.md` 逐故事实测
  (真实浏览器、真实数据、真实 LLM 配置),每故事至少一组前后对比截图入
  `evidence/<date>-<story>/`,逐条判定期望效果是否成立;结论与偏差回填
  `findings.md` 复验记录区。
- **代码测试是护栏不是验收**:语义修复(失效链路、链接投影、deref 回退、成败
  标注)按 TDD 先写失败测试再实现,保证 `pnpm vitest run` 相关项目与
  `pnpm governance` 全绿;但故事关闭只认视觉走查证据。
- **每轮走查的固定评审项**:无每应用/每实体特判代码;无渲染器新增文案模板;
  处境装配点未增;GR1–GR5 照常。
- 治理照旧:`pnpm check` 全绿;业务优先原则适用于行数门禁(超限登记例外,不为
  凑数裁剪)。

## Scope 边界(非目标)

- 不做首页助手栏前置 / AI 前置形态重构(T33 已出 scope,另立 track);
- 不做事件驱动活性推送(刷新由动作触发,不做后台自动推送);
- 不改引擎裁决序、确认门语义、Cedar 策略与 human-only 闸;
- 不做 LLM Presentation 规划接管(仍 generic + 组合机械规划);
- 不推翻 D47.4(actions 始终保留)与 D47.1(通用文案框架 + 合同插值);
- 不动 D51 授权/注意力语义(注视仍只出自 situation 单点;本 Track 只修坏事实
  与其呈现);
- 不新增每实体/每应用特判代码;不在渲染器新增硬编码友好文案模板;
- 元数据/字号级别的视觉打磨(字体、配色体系)不在首轮,除非阻塞故事判定。
