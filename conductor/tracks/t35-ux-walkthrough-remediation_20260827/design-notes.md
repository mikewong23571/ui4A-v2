# T35 设计笔记 — 工作线(work thread)如何承载用户的业务目标

> 性质:设计审查记录,非缺陷台账(findings.md 管问题实情)、非 spec(不直接构成
> 验收)。源于 2026-08-27 用户命题:"思考 thread 的业务目标;如何承载用户的业务
> 目标。不是某个实例化之后的业务目标,而是从整个 workstation 的角度、整个应用
> 设计目标的层级审查。" 裁判文书:`conductor/product-vision.md`(§四为主)。

## 一、北极星里,线是什么

vision §四:"用户的工作单位不是应用,是'一件事':一个目标 + 一包上下文(跨 scope
实体)+ 进行中的 flow/run + 待批准项 + 最近事件。它是纯投影,不是新真相;是
scoped context 的真正载体,**是首页的主角**,也是 AI 上下文的边界。conductor 的
track 目录就是它的人工版。"

最后一句是关键对照:一个 conductor track 目录携带 spec(为什么做、做成什么样算
成)、plan(现在到哪、下一步是什么)、findings(路上发现了什么)、evidence(证据)。
**工作线的业务目标,在应用设计层级,就是让人和 AI 在任何时刻都能回答三个问题:**

1. **这是哪件事**(目标句 + 为什么/来源);
2. **现在到哪了**(上次停在哪、什么在跑、什么在等我点头);
3. **下一步该谁做什么**(我的责任点在哪、AI 正在推进什么)。

application 是图书馆,线是书桌(§四)。家的默认阅读单位必须是线,不是机器平面。

## 二、workstation 全局审查:陈列轴错了位

现状(R1 走查,`findings.md` F-11 及首页观察):首页三区并列——在等我(`inbox`)/
在动(`delegations`)/我的工作线(`threads`)。这是**机器平面的陈列轴**(按实体
种类),不是**用户的陈列轴**(按"事")。后果:

1. **活动不归事**:"在动"的委托/运行其实是"某条线在动",但首页看不出哪条线;
   "在等我"的确认卡也不携带所属线——等待与推进都悬浮在"事"之外;
2. **目标出生即失忆**:创建线时填了"目标/目标来源"(T26 投影含 goal),但线详情
   页与首页卡片都不再呈现 goal——用户亲手写下的业务目标,UI 里再没出现过;
3. **线详情是动作堆不是叙述页**(F-11):URN 标题 + 五个等宽按钮 + self 卡;
   T26 已投影的目标/引用/进行中/待批准/事件切片全部缺席;
4. **状态机 ≠ 进展叙述**:"停在「open」"是流程语;"上次停在哪、下一步是什么"
   才是任务语(T33 方向,未落到线卡);
5. **线与处境关系弱**:顶栏可声明工作线,但首页不呈现"我现在坐在哪条线上";
   线之间无主次,书桌隐喻没有落地。

根因不是缺数据——T26 的 ThreadSnapshot 已含 goal/owner/status、四类引用、
进行中、待批准、有界事件。**缺的是投影的"叙述组装"与首页的"主角位"。**

## 三、业务目标的四个承载层(设计判断)

**Layer 1 · 目标即身份。** goal 是线的标题性存在:线详情页 H1 用业务标题、其下
第一行是目标句(来源小字);首页线卡第一句同源。零新真相——纯读 snapshot.goal。

**Layer 2 · 目标即参照系。** "到哪了"只能相对目标叙述:进行中的 run 是"谁在为
这件事跑"、待批准是"这件事在等我点头"、事件切片是"这件事最近发生了什么"。
T26 的显式引用聚合已把这些挂到线上,投影按线叙述即可(规则滑梯红线:成员资格
保持事件显式引用,零 type 分支)。

**Layer 3 · 目标即共同处境。** scope=线(§三):AI 开口即知"我们在办哪件事";
引用包让"这个/那个"可解(§二指代可解);线的认知边界 = 助手上下文边界(§一.3
"AI 看到的和你看到的是同一个东西"在线级成立)。

**Layer 4 · 目标即结案回执。** complete/archive 时线应沉淀"结果一句话 + 关键
证据引用"——conductor track 的 done-report 对应物。事件投影可回放,仍零新真相
(结果句可作为 complete 动作的合同参数/事件 detail,叙述由投影生成)。

## 四、workstation 承载形态(演进方向)

- **A. 首页:从"三区并列"到"书桌 + 书架"。** 当前线(声明中的或最近活跃的)升
  第一屏主角卡:目标句 + 停在哪(任务语)+ 该线在动 + 该线等我;其余线一行一条。
  纯投影重组(聚合虚主体,T30 机器),动作保留合 D47.4,零引擎改动。
- **B. 线详情 = 叙述页**:目标(身份)→ 上下文包(可点引用)→ 进行中(谁在跑)
  → 待批准(等我点头,决策卡一击,T33)→ 最近事件(叙述切片)→ 动作(分组、
  危险分层)。F-11 的修法即此,user-stories **S8** 是其最小实现。
- **C. 陈列轴补链**:在等我/在动条目携带所属线回链(有则显示);机器平面集合
  不删(审计/raw 价值),但家的默认阅读轴让位给线。
- **D. chat 分工不变**:线的"推进"正典在 chat(说人话→助手执行,原话授权),
  线的"责任点"在线卡(一击批准);线页不退回表单堆(T33 已定)。
- **E. AI 上下文边界 = 当前线**:assistant 在线内 scoped Q&A,跨线靠显式导航
  留痕(§一.2 上下文来自客户端事实)。

## 五、与 T35 的关系

- S8(F-11)按 B 的方向修,是 Layer 1+2 的最小落地;
- A(首页书桌化)涉及首页区域构成与聚合声明(T30 口径/声明版本升级),超出
  T35 首轮 scope——**登记为方向项,待 F 轮或另立 track**;
- C/D/E 属后续轮次增量;本笔记作为各轮设计依据,修改须先改文档再改码。
