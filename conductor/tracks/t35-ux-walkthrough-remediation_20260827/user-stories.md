# T35 用户故事(文档化视觉验收锚)

> **本文件是什么**:T35 的验收准绳。每个故事描述"一个使用者会经历的最终效果",
> 验收方式是**编排 agent 以使用者身份在真实浏览器里按步骤实测,用视觉能力对照
> 本文档逐条判定**,截图存 `evidence/<date>-<story>/`。
>
> **本文件不是什么**:不是单测断言、不是代码验收清单。**禁止以单测/代码检查
> 替代故事验收**;代码层测试只作语义回归护栏(见 spec 验收协议)。
>
> 判定纪律:期望效果里每一条加粗句都是可判定的视觉事实;任何一条不成立即故事
> 不通过,偏差回填 `findings.md`(新编号或挂靠既有编号),修复后重走。
> 验收环境:本地 dev(pnpm dev:all,web:3100),真实 LLM 配置,数据可现场创建。

---

## S1 回家一眼(我的事读面)

- **角色**:每天打开 UI4A 推进工作的使用者。
- **场景**:登录后落在首页,想知道"现在有什么在等我、什么在动、我的线到哪了"。
- **步骤**:打开 `/`(带一条 pending 确认、一条进行中工作线的状态),观察首屏。
- **期望效果**:
  1. **3 秒内能说出三件事:什么在等我(几件、是什么)、什么在动、有哪些工作线**;
  2. **区块计数只出现一次**,与卡片实际数量一致;
  3. **页面无重复样板句**(同一句话不在同屏出现两次);
  4. **没有 `self` 徽章的空链接卡**;空区块呈现一句引导或留白,不放结构噪音;
  5. **待批卡片一眼可辨**(风险/来源/对象在视觉中心),批准与驳回是不同视觉层级;
  6. **导航、页题、内容标题对同一概念用同一个名字**(F-05 术语表)。
- **关联**:F-05/F-06/F-07/F-12;证据基准 `evidence/2026-08-27-initial-walkthrough/01_home_top.png`、`02_home_bottom.png`。

## S2 一击闭环(批准)

- **角色**:被助手/agent 请求授权的使用者。
- **场景**:首页"在等我"有一张 agent 提议的归档确认卡。
- **步骤**:点 [批准] → 停留观察 3 秒;再点页内"重新载入"。
- **期望效果**:
  1. **点击后无需整页刷新:卡片当场退场,"在等我"计数当场减一**(按钮 pending 态
     或轻量回执可选,投影更新是硬要求);
  2. **页内"重新载入"点击前后画面一致**(它不再是救场手段);
  3. **浏览器整页刷新后状态与屏上所见一致**(屏上即真相,不是缓存假象);
  4. 全程**无孤零零的静默**——要么投影变化本身可见,要么有结构化回执;不允许
     "点了但看不出任何变化"。
- **关联**:F-01;对照基准 `05_after_unpublish_no_feedback.png`、`07_hard_reload_shows_offline.png`。

## S3 状态即变(下线/重新发布)

- **角色**:内容发布应用的使用者。
- **场景**:在画布打开一篇 published 文章详情。
- **步骤**:点 [下线] → 观察;点 [重新发布] → 观察;中途点一次页内"重新载入"。
- **期望效果**:
  1. **点下线后,状态词当场变为已下线,动作区当场换成"重新发布"**;
  2. **点重新发布后,状态词与动作当场还原**;
  3. **"重新载入"永远显示与屏上一致的状态**(无缓存回退);
  4. 文章列表页与详情页状态一致(导航即见,无需刷新)。
- **关联**:F-01;对照基准 `04_article_focus.png`~`07_hard_reload_shows_offline.png`。

## S4 直操作建线(创建工作线)

- **角色**:想自己开一条新工作线的使用者(不走聊天)。
- **场景**:首页"我的工作线"区。
- **步骤**:点新建入口 → 填表 → 提交 → 观察列表。
- **期望效果**:
  1. **入口叫"新建工作线"类的动作语,不叫"填写创建工作线参数"**;
  2. **表单字段说业务语言**(名称/目标/来源),每个必填项有占位或示例提示,
     不要求用户自造机器标识(或把标识标注为可选/自动生成);
  3. **提交后表单收起,新线当场出现在列表**,带可读标题与状态;
  4. **页面上不存在第二个隐藏的同名提交按钮**(F-15)。
- **关联**:F-01/F-08/F-15;对照基准 `21_create_thread_form.png`、`22_create_thread_no_feedback.png`。

## S5 跨面跳转不死(查看活实例)

- **角色**:在 meta 检查流程定义的治理者。
- **场景**:流程定义详情点"查看活实例"。
- **步骤**:定义管理 → 流程定义 → 任一有实例的流程 → 顶栏"查看活实例"。
- **期望效果**:
  1. **落点是该流程真实实例的集合视图,成员可见**(不是"实体不存在"空页);
  2. **顶栏处境条与落点一致**(注视指向真实存在的目标);
  3. 若目标确实不存在(如空实例),呈现**结构化空态**:说明"没有实例"+ 至少一个
     可操作出口(返回定义/调整声明),而不是一行孤立红字;
  4. **这次跳转之后的聊天新会话不受污染**:发送首页建议任务(如「发布一篇文章」)
     能正常走流程。
- **关联**:F-02;对照基准 `12_cross_plane_dead_end.png`、`15_chat_fail_flow_gaze.png`。

## S6 与助手同看一页(聊天共同完成发布)

- **角色**:把"写"交给助手的使用者。
- **场景**:展开聊天,发送「发布一篇文章」。
- **步骤**:按助手澄清逐轮回答(标题→分类→正文)直到完成;全程观察右侧画布与
  助手消息;完成后打开"历史会话"。
- **期望效果**:
  1. **澄清问题是业务语言**(问标题、给可选项),不出现"next 动作必填字段"式
     合同方言;
  2. **画布与助手同步可读**:要么向导面正常渲染可跟随,要么呈现聚合后的单条
     可读进展说明——**同文错误行不得堆叠出现**(≤1 条 + 可展开详情);
  3. **发布完成后,文章以已发布状态可见**(画布或列表),助手汇报与事实一致;
  4. **助手在目标达成后收敛**,不再执行多余步骤;
  5. **历史会话中该会话的成败标注与业务结果一致**(发布成功 ≠ "失败");
  6. "依据/引用"类 chip 可读且可点,JSON path 只出现在可展开的审计层。
- **关联**:F-03/F-04/F-09;对照基准 `17_canvas_4_errors.png`、`18_chat_evidence_paths.png`、`28_session_history_false_failed.png`。

## S7 流程定义可读(meta 读面)

- **角色**:低频进入 meta 的治理者。
- **场景**:查看流程定义列表与某流程详情。
- **步骤**:定义管理 → 流程定义 → post-status(文章状态)详情 → 底部动作区。
- **期望效果**:
  1. **列表卡片与详情标题同名**(中文业务名,raw id 退居次要位置或省略);
  2. **状态节点与版本卡的层级分明**(成员区不再混入无标题的 `meta · definition-version` 卡);
  3. **禁用按钮的原因说人话**(由结构化原因 + 合同插值/LLM 转述,不裸奔 guard 表达式);
  4. **界面无开发注释口吻文案**(如"不代表生产 SSO""不冒充特化体验"改写为
     使用者视角或移入说明抽屉)。
- **关联**:F-05/F-10/F-16;对照基准 `09_meta_flows_list.png`、`10_flow_post_status.png`、`11_flow_actions_guard.png`、`08_meta_console.png`。

## S8 一件事的投影(工作线详情)

- **角色**:推进某条工作线的使用者。
- **场景**:从首页进入自己的工作线详情。
- **步骤**:首页点工作线卡 → 观察详情页 → 回首页。
- **期望效果**:
  1. **标题是业务标题**(处理 webflux 批次 CVE),不是 URN;
  2. **一眼看到:目标、当前状态(人话)、挂载的显式引用、最近发生了什么**
     (全部来自既有投影,不加新真相);
  3. **动作分组呈现**,危险动作(归档/暂停)与常规动作视觉分层,不再等宽整行堆叠;
  4. 状态只说一遍(不再"停在家『open』"+"open · thread:xxx"双份)。
- **关联**:F-07/F-11;对照基准 `27_thread_focus.png`。

## 验收执行说明

1. 每轮验收 = 逐故事走查 + 截图(前后对照),存 `evidence/<date>-<story-id>/`;
2. 每故事给出 通过 / 不通过(逐条列出未成立的加粗项);
3. 不通过项回填 `findings.md`(新 F-XX 或挂靠),修复后仅重走受影响故事 + 关联回归故事;
4. 全部故事通过且无未处置 P0/P1 findings 时,该轮修复阶段方可闭合;
5. 本文档的修订(新增故事、修改期望)必须先改文档再改码——**文档先于实现**。
