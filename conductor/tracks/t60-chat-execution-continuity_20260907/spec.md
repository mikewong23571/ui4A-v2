# T60 聊天执行连续性

## 问题与范围

会话 d334af87 在一个用户回合中连续执行相同工作线创建三次，随后否认创建。
线上 core 事件 1447、1458、1466 的授权均指向用户消息
443d7e94-7eba-486e-9dea-935430e2248b；并非三个用户提交或历史同名记录。

修复参考 Assistant 的命令身份及执行事实披露，保留 LLM 自主选择操作。
不通过自然语言关键词、同名业务去重或自动 done 判断代替模型。
不修改生产数据、不清理这三条工作线、不在本 Track 中发布。

## 验收

1. 同一次 run 内，同授权原话、同 rel/action/caller 参数的 client-owned commandId
   稳定覆盖模型重复提议与传输重试；caller 参数键顺序及模型伪造 client 字段不改变身份。
   新 run、不同目标、不同 action/rel 或不同授权消息保持独立；不宣称跨进程恢复保证。
2. 重复请求仍走 HTTP 与引擎重放裁决；真实工作线 kernel 最终只有一次出生事件。
3. 工作线四类成功事件的 receipt 进入同一 execution audit，包含真实执行实体、actor、
   授权原话和事件序号；不生成第二份业务日志，不改变业务 fold。
4. Chat 执行处境按 principal 与当前 session 的授权消息关联后再限量，其他会话的操作
   不挤走本会话记录。缺证据不能被模型解释为“未执行过”。
5. 当前 run 的成功披露包含返回实体引用与授权消息 ID，原始 Assistant 文本保持不变；
   回答执行问题以机械回执为依据，允许纠正此前错误回答。
6. 覆盖重复创建、下一轮追问、同 principal 两 session、跨 principal 碰撞、重试和新请求；
   focused tests、pnpm check 及真实模型验证分别记录边界。
