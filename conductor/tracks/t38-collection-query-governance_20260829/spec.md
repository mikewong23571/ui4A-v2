# T38 集合查询治理 — Specification

## 类型

Feature(集合规模查询能力 + 实体显示 hint:合同层分页、声明式过滤、
声明式概览列;跨定义/投影/呈现三层)

## 问题(现状已核实)

- **全量平铺无分页**:`projectCollection` 把集合全部成员(含完整投影、
  actions、guard-results)嵌入单个响应;呈现层 repeat 全量渲染。规模压力
  三重:响应载荷、DOM 节点数、逐成员解引用成本。
- **无过滤**:查询型场景(「只看待处理评论」)只能全量扫行;披露无法按需
  收窄。
- **无概览显示 hint**:集合行(表格/卡片)显示哪些字段是词条写死的
  (identity/status/detail),应用定义无从声明「我的实体在列表里该露出
  哪些字段」——字段多的实体概览信息不足,详情面才有全量。
- **合同红线**:分页/过滤不得窄化 HTTP 合同——不带参数必须仍返回全量
  (CLI/外部 agent 的全量发现面是合同承诺,product-vision §二 CLI 三纪律)。

## 方向依据(北极星)

- **§二 同一扇门/CLI 三纪律**:披露收窄发生在呈现层,不窄化 HTTP 合同;
  分页/过滤/hint 人机同门——agent 经 sitemap/entity 投影发现同一能力与
  同一显示语义。
- **§五 披露按需**:减法减的是"一次灌全部",加法加的是"按声明收窄"。
- **§六 不做传统软件**:过滤维度、分页形态、概览列全部来自声明数据
  (应用定义/sitemap/投影),渲染器零发明;固定评审项:**无每应用/
  每实体类型特判代码**。
- **D51**:授权 = grantedApplications × fold audience;分页/过滤是读面参数,
  不得成为鉴权输入,不得跨 principal 泄漏任何行。

## 功能需求

### FR1 集合投影分页(合同层;服务端驱动)

- `GET /api/entity?rel=<collection>` 支持可选分页参数(如 `limit` + `cursor`
  或 `offset`;具体形态实施期按集合投影现状定);**不带参数 = 全量**,现有
  响应形状逐字节不变(合同零窄化,既有测试锚定)。
- **页大小是投影策略,不是前端常量**:渲染器不推算页码、不携带分页尺寸
  常量,只跟随合同声明的 `next`/`prev` 链接(FR2)——传统分页组件
  (页码列、每页 N 条选择器)按 §六 判据退回。
- 分页仅对集合实体生效;非法参数值 → 结构化拒绝(拒绝即教育,不静默忽略)。

### FR2 页面导航声明(合同层)

- 分页响应在集合实体 links 声明 `next`/`prev` 页面链接(带分页参数的
  href;`self` 既有)。无更多页时诚实缺链。
- 渲染器只渲染声明链接,不发明任何页码推算。

### FR3 过滤维度声明与投影(合同层)

- sitemap 集合表面(或集合投影)声明可过滤维度与合法值域;**声明与值域
  必须住在定义平面数据**(应用 bundle 显式声明,或从流拓扑/节点名推导的
  声明数据),service 层禁止任何「集合名 → 维度/值域」特判映射(§六 规则
  滑梯:可治理的声明数据,迟早经 meta 定义,引擎只做 fold)。
- 投影接受过滤参数;过滤值必须属于声明值域,否则结构化拒绝。
- 过滤 + 分页可组合(先过滤后分页,页面链接携带过滤参数)。

### FR4 实体显示 hint(定义层 → 投影 → 呈现,声明式概览列)

- 应用定义可为实体声明「概览显示」hint:哪些字段进入集合概览行、列标题
  与顺序(机制优先复用既有字段角色体系 `presentation.fields` 的 role/
  扩展,避免第二套平行机制;实施期定型)。
- hint 经实体投影携带到成员(人机同源:agent 读同一投影获得相同显示
  语义);member-table(及 member-card 的 detail 位)按 hint 渲染概览列。
- 无 hint 时回退现状(identity/status/detail),诚实不发明;hint 值必须
  引用声明过的字段,引用不存在的字段按投影校验拒绝/忽略并留诊断。

### FR5 呈现(呈现层,声明驱动)

- member-table 集合区域渲染:概览列按 FR4 hint;分页脚(仅声明的 next/
  prev 链接)+ 过滤控件(仅声明维度;值变更 → 携带参数重新取数)。
- **过滤/翻页是读面导航机械,永不 exec**:控件只改查询状态(URL query),
  不映射任何业务动作、不产生业务事件(action-backed 铁律管辖业务操作,
  此处属舞台机械的查询导航,与 scope/focus 同族)。
- **控件文案零硬编码**:维度标题、值标签只来自声明数据(字段标题/流节点
  标题);渲染器不写任何 per-app 文案(§六 文案滑梯)。
- 分页/过滤状态进入 URL query(可分享、可回放、刷新保持);policy scope
  全程保留。
- 零 per-app 分支:同一套渲染机器吃所有应用的声明;无声明维度/单页集合
  时不渲染任何分页/过滤机制零件(诚实空态)。

### FR6 双门一致

- CLI/合同探针经同一 sitemap/entity 投影发现分页、过滤能力与显示 hint;
  无参数全量承诺以测试锚定(CLI parity)。

## 非功能需求

- GR1–GR5 全过(基线零例外;超限沿功能边界拆解,D53)。
- D51:分页/过滤参数不进入任何鉴权签名;行级授权(fold audience)逐行
  不变——过滤/分页后仍逐行过授权投影。
- 零新事件类型(读面能力);重放语义不变。
- 披露收窄不窄化 HTTP 合同(FR1 无参数全量是验收硬项)。

### §六 对齐自查(评审固定项,Phase/终审逐条对照)

- 换应用判据:分页/过滤/hint 的任何代码换一个 application 不需要改;
- 页面滑梯:无分页/过滤专用页面组件,全部是 member-table 词条内的声明
  驱动呈现;
- 特判滑梯:无 `if 集合名/实体类型` 分支(维度/值域/hint 全部声明数据);
- 文案滑梯:控件标签/值标签只来自声明标题,渲染器零 per-app 文案;
- 规则滑梯:值域无 service 特判映射,只住定义平面数据;
- 分页无前端页码推算、无页大小常量(服务端驱动,只跟随声明链接);
- 过滤/翻页永不 exec,零业务事件。

## 验收:用户故事闭环(agent 浏览器视觉审核,非 Playwright;**全应用横扫**)

> 沿 T37 验收模型:编排 agent 浏览器实操 + 截图 + DOM 断言,逐故事留证
> track `review.md`;不写任何 Playwright 脚本。**验收必须 review 全部已装
> 应用**(publishing/community/development/editorial/governance/todo/ideas
> 及平台集合),逐一确认展示效果,不止抽样三个。

- **U1(publishing)分页**:经合同门(CLI/exec 批量)创建超过页大小的成员
  (顺带验证 agent 同门批量路径)→ 表格出现分页脚;点 next/prev 翻页;
  URL 参数变化、刷新保持、scope 保留。
- **U2(community)过滤 + hint**:声明的状态过滤控件 → 筛选 pending 只见
  待处理行;过滤 + 翻页组合;概览列按 hint 显示声明字段。
- **U3(publishing)hint 概览列**:文章集合行按声明的概览 hint 显示字段
  列(如 分类/标签),无 hint 字段不进概览;详情面全量不变。
- **U4 全应用横扫**:逐一进入 7 个应用默认组合面 + 关键集合,截图审:
  表格/卡片按声明渲染、分页/过滤零件只在声明处出现、零诊断兜底、既有
  功能(行内动作、详情链接)无回归。
- **U5 合同门**:curl 无参数全量(与 CLI 一致);带参数分页/过滤形状正确;
  非法参数结构化拒绝;hint 经投影可被 agent 消费(双门一致)。
- **U6 零特判 + 授权不变**:git diff 无 per-app/per-entity 代码;过滤/分页
  前后行级授权投影一致(D51 回归断言)。

## Out of Scope

- 全文搜索(只做声明维度过滤);
- 无限滚动/虚拟化(分页是本 track 的唯一规模化答案);
- 组合面标题人话化、区域级表头(既登记观察项,后续 track);
- 详情面改版(hint 只影响集合概览行)。
