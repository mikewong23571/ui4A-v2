# T56 Spec

## 1. 目标与完成定义

用户单位是“一件事”，不是某个 Application，也不是某个 chat session。
工作线页面必须帮助人恢复目标、理解进展、作出知情决定、追溯依据，并让助手共享当前处境。

阅读顺序：**目标 → 当前处境 → 本次要判断/阅读的内容 → 依据 → 当前合法动作**。
成功不是少一栏或换皮肤，而是减少恢复上下文、找对象、查证与跨页拼接的成本。

完成定义：US01–US12 全部有可复核证据；G1–G7 必需门禁通过；实现后 review、修复和复审完成；
所有无法执行的验证明确记 NOT RUN，必需验证未执行则 track 不得完成。
五秒恢复工作的体验目标只作真人观察，不能伪装成自动化证明；具体测量见 acceptance.md。

## 3. 必须保留的产品与架构约束

1. D44：工作线 principal-owned、跨应用、跨 session；成员只由显式 attach/detach 事件决定。
   不从访问、聊天文本、同名、业务类型或 rel 图自动扩大工作线。保留现有用户消息经
   `attachChatMessageToThread` 显式 attach 到已创建且 owned 工作线的接线；不扩大其对象范围。
2. D51/D58：注意力≠授权；只用凭证授予×事实归属裁决。人和 agent 从授权合同共读，
   浏览器常显与发送 clientView 同源；UI 收起不窄化 HTTP 发现合同。
3. D27/D45/D46/D54：内容面由合同/声明/Presentation 生成，保持 binding-only、逐源授权、
   Sidecar/Recipe 依赖与重放；不复制一套 React 业务 dashboard。
4. D47/D50/D74：动作来自当前 Siren，提交前 fresh read，服务端同一裁决与确认通道。
   高风险、选择门、human-only approve、审计零 AI 均不变。工作流的“自治验收”
   仅是代码/文档验收，不授予 agent 业务审批权。
5. D28/D68：AI 临时解释不是新业务真相；会话按 principal×sessionId 归属。
   进入/离开工作线不自动新建、换绑、删除或过滤掉当前会话。
6. GR1–GR5：无每应用/领域实体类型分支，无新状态库、无新依赖、无双实现长期并存；
   历史 track 不改写。先记录替代设计决定，再删除约束恒三栏的代码/测试。

## 4. 功能要求

### FR1 工作线是主内容主体

`thread=T&focus=thread:T` 进入本线概览；`thread=T` 无其他显式 focus 时也有可解释本线落点。
`thread=T&focus=X` 进入 X，保留 T 的身份与返回路径。不得把本线视作 noGaze 展示全量应用书架。
无 thread 的应用发现与首页最多九个应用的规则保持；直接访问对象不强制创建工作线。

### FR2 目标、状态、责任、依据有清晰层级

常显完整可读的目标/身份、生命周期状态与当前对象；避免相同状态重复叙述。
概览内容包含当前可见责任、进行中的显式关联项、相关材料及最近显式关联事件的到达路径。
关键责任不能被 AI、空白概览或“已归档”状态隐藏；读取失败与确实为空分开。
阅读某对象时保留用户显式 focus，新状态到达只更新事实/提示，不自动抢走阅读位置。

### FR3 按处境安排注意力，不发明新业务状态

open/paused/completed/archived 仍是原生命周期；“等待我决定”“正在阅读”是呈现姿态，
不得写成另一份 thread 状态。目标标准、阻碍、产出、验收结论只在有授权来源和声明语义时显示。
仅有材料关联不代表产出；仅有 completed/archived 不代表验收通过；无证据如实表达未提供。
存在未完成责任的归档线仍能到达该责任，不能错误宣称“无需处理”。

### FR4 一主工作面与响应式协作

默认去掉永久左材料栏，保留明确“相关材料”入口；助手展开时至多主面＋助手两栏。
剩余空间不足则助手切为可关闭的覆盖层或单面切换，不能挤窄主对象。
不缩字号解决布局问题、不把关键正文/对象标题/决定动作设为省略号；具体宽度、焦点和滚动契约见 design.md。
本 track 不新增三栏可选模式、可拖拽布局编辑器或偏好持久化服务。

### FR5 材料关联与视图钉住语义一致

材料列表与“已在本线”只读合同 membership；添加/移除走现有选择器与 attach/detach。
本地 pin 只表示视图快捷入口，改称明确的“固定视图/取消固定”等舞台文案，不能标作“挂进本线”。
允许复用既有 pin 存储；不自动转为业务关联。仅取消 pin 不产生业务事件；detach 成功前
不移除材料或同时清 pin。归档无动作时不显示可提交添加/移除；失败状态不可假成功。

### FR6 知情决定在同一工作面闭环

本线关联责任可直接到达同一主面的现有确认/决策词汇。
默认展示目标、操作、可获得的改变前后、依据、影响/风险及声明动作；
没有历史前值/影响声明时不补造，不用当前值假扮批准时依据。
执行后保持决定回执可读，更新本线与目标，并从 fresh actions 移除失效操作。
Meta 治理必须保留显式跨站及可信机械审查宿主，不在工作线复制可被提案者控制的审批 UI。

### FR7 聊天的当时与当前明确分开

输入附近可查看当前工作线/对象，与实际发送的 clientView 一致。
历史回合按持久化 turnId、时间及当时结构化 clientView 恢复；上下文缺失则明确未知。
会话可以跨工作线；不得按当前 URL 给所有旧消息重新贴标签，也不自动新建会话。
切布局、窄屏展开、关材料目录都不丢草稿、流式回合、停止能力或会话选择。

### FR8 依据可辨、可达且时点诚实

每个引用能区分“哪个对象/哪类依据”；标签只来源于声明身份/字段标题及已记录证据，
不得解析回答自然语言来猜目标。点击保留线与导航上下文，落到可证明的目标；无字段定位能力不假称定位。
集合 JSON Pointer 的数组位置不是永久实体身份：历史引用不能拿今天的第 N 项推断当时对象。
原引用 rel/pointer 必须保留；缺少历史 identity/snapshot 时显示集合级依据、路径与时点边界，
而非显示一个可能错误的具体对象名。实时标题必须表明是当前名称。

### FR9 低暴露而可恢复

raw、why、重新载入、会话 ID/机械轨迹保留按需到达，首次阅读以业务标题与正文为主。
loading、empty、partial、denied、network、LLM unavailable 各有诚实状态和合适出口；
引用读取不可用不导致整条线空白，不为消除空白而伪造事实。

### FR10 同门与持续新鲜度

同一 fixture 下人类 UI、只读 HTTP/CLI 与 Assistant 披露使用同源的授权事实。
成员变更、动作结果、生命周期变化、授权变化要更新相应依赖；同 rel 内容更新也不能继续显示旧事实。
无隐藏全库扫描、无全量 sitemap 注入、无根据业务状态名猜下一步的规则智能。

## 5. 非目标与交付边界

- 不部署、不推送、不改域名/认证/模型配置、不清理线上体验数据；发布另按部署 runbook 授权。
- 不实现自动工作流推进、新的验收状态机、结果资产体系、消息搜索系统、全站导航重设计。
- 不为补齐概览猜测阶段、完成率、责任、风险、截止时间或“下一步建议”；有事实就展示，
  需要认知解释由已配置 LLM 按用户意图完成。
- 不把当前演示应用名/想法字段名写进通用组件，不重做 T54 已有确认卡和会话能力。
- 不借本次改动修完 T54 所有遗留缺口；只承担 FR1–FR10 及其必要回归。

依赖基线已包含 T26/T30/T35/T39/T42/T49/T54/T55，均属历史输入，不恢复它们的陈旧实现约束。
计划依据与全部验收步骤在本目录；实施时必须重新检查 HEAD、工作树及相关合同，不把上述样例当实时事实。
